# Runtime dynamic dispatch for Any and Union types

This change adds runtime type dispatch for arithmetic, comparison, truthiness, str/print, len, iteration, and indexing when the checker sees Any or Union operands. A new 582-line file (`operator/dynamic.go`) implements all host functions that use NaN-boxed `Boxed.Kind()` to determine runtime types and dispatch to the appropriate concrete operation. The checker, lowerer, and builtins packages each grow small gates (`isDynamic`/`isDynamicEmit`/`refDynamic`) that route through these host functions instead of rejecting the operation or emitting static opcodes. Static paths remain untouched: isinstance-narrowed and specialized code still produces direct opcodes.

Watch for: `dynCmp` produces wrong results for cross-kind comparisons like `"abc" == 0` → true (confirmed), dict/set operations are entirely missing from runtime dispatch (confirmed), `dynTruth` doesn't handle TypedArray for list truthiness (confirmed), and the `isDynamic` predicate is copy-pasted five times across four packages violating one-canonical-definition-per-concept (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The design routes every dynamic operation through a single decision point per package layer: checker admits the operation (returns `Any`), emitter calls a `Dyn*` host function, and the host function does `Boxed.Kind()` dispatch at runtime. Static paths remain untouched — isinstance-narrowed code still produces direct opcodes with no dynamic overhead.

The runtime dispatch covers numeric arithmetic (int/float with proper Python floor-division/modulo), string concatenation and repetition, numeric and string comparison, truthiness, iteration, indexing, and membership testing. Dict, set, and tuple operations are absent: `dynIndex`, `dynLength`, `dynIterator`, `dynIn`, and `dynTruth` only probe for strings and arrays. Any dynamic operation on a dict/set value will produce `ErrTypeMismatch` at runtime.

The `isDynamic` predicate logic is duplicated five times across four packages with inconsistent `types.Erase` usage. The coding standard requires one canonical term per concept. A single exported `types.IsDynamic` would consolidate all copies.

Test coverage is thorough for the happy path (26 subtests). No error-path tests exist: division by zero, index out of range, type-incompatible operations, and cross-kind comparison semantics are untested.

## Cross-kind comparison fallthrough bug

`dynCmp` has three sequential guards: string comparison (both KindRef), None comparison (either is null ref), then a final numeric catch-all using `toFloat()`. When one operand is a ref-kinded non-None value (string, list) and the other is numeric (KindI64/KindF64), no guard catches it:

```go
// Guard 1: both KindRef → string compare or identity
if lk == vmtypes.KindRef && rk == vmtypes.KindRef { ... }

// Guard 2: either is null ref → None compare
if lk == vmtypes.KindRef && left.Ref() == 0 || rk == vmtypes.KindRef && right.Ref() == 0 { ... }

// Catch-all: numeric comparison
lf, rf := toFloat(left), toFloat(right)
return cmpFloats(lf, rf, op), nil
```

For `"abc" == 0` (left=KindRef non-null, right=KindI64): guard 1 fails (right isn't KindRef), guard 2 fails (left.Ref()≠0, right isn't KindRef). Falls through to `toFloat(left)` which returns 0 for KindRef. `cmpFloats(0, 0, EQ)` → true. In Python, `"abc" == 0` is `False`. The fix is a type-homogeneity check before the numeric catch-all: if kinds disagree and either is KindRef, return false/error.

## Dict/set gap in runtime dispatch

Every dynamic host function uses a two-step probe: try `hostabi.LoadStr` (string?), then try `hostabi.ArrayElems` (list/array?). Neither probes for `*vmtypes.Map`. Since minipy represents dicts and sets as maps at the VM level, operations like `d: Any = {"a": 1}; d["a"]` or `len(d)` or `for k in d:` will all fail with `ErrTypeMismatch`. Adding map support requires `i.Load()` + type assertion on `*vmtypes.Map` and the corresponding MAP_GET/MAP_LEN/MAP_ITER dispatch.

## TypedArray truthiness gap

`dynTruth` handles `*vmtypes.Array` but not `vmtypes.TypedArray[T]` (the representation for homogeneous lists like `list[int]`). An empty `list[int]` passed as Any would reach the `default: return true` branch — wrong Python semantics. The simplest fix is to use `hostabi.ArrayElems` (which normalizes all array representations) and check `len(elems) > 0`, or add explicit TypedArray assertions matching what `ArrayElems` already handles.

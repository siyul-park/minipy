# Runtime dynamic dispatch for Any and Union types (v2)

This change adds runtime type dispatch for arithmetic, comparison, truthiness, str/print, len, iteration, indexing, membership, and unary operators when the checker encounters Any or Union operands. An 806-line `operator/dynamic.go` implements all host functions using NaN-boxed `Boxed.Kind()` dispatch. The checker, lowerer, and builtins packages each contain small gates that route through these host functions instead of emitting static opcodes. Static paths remain untouched: isinstance-narrowed and specialized code still produces direct opcodes. All seven v1 issues have been addressed — canonical `types.IsDynamic()`/`types.IterableElem()` replace duplication, cross-kind comparison uses a type-homogeneity guard, dict/set support is added throughout, TypedArray truthiness uses `hostabi.ArrayElems`, unary operators are dynamicized, and error-path tests are in place.

Watch for: `DynStr`/`DynPrint` delegates to `FormatScalar` which renders non-string container refs (lists, dicts) as `"None"` instead of their Python representation (confirmed). `intPow` returns 0 for negative exponents instead of raising `TypeError` or returning a float as Python does (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The design routes every dynamic operation through a single decision point per package layer: the checker admits the operation (returning `Any`), the emitter calls a `Dyn*` host function, and the host function does `Boxed.Kind()` dispatch at runtime. Once a type is narrowed through isinstance or specialization, the emitter skips the dynamic path entirely and produces direct opcodes.

`DynStr` and `DynPrint` delegate to `hostabi.FormatScalar`, which only handles scalars and strings. Any container ref (list, dict, set) passed through these paths renders as `"None"`. The static `str()` path uses `hostabi.FormatValue` which accepts a source type for proper container rendering — information the dynamic path doesn't have at compile time. This is the most visible Python-incompatibility remaining: `x: Any = [1,2,3]; print(str(x))` prints `None`.

`intPow` returns 0 for negative exponents. CPython returns a float (`2 ** -1` → `0.5`). Returning 0 silently is a correctness gap — either return a float result or raise an error.

## str/print on Any-typed containers

`DynStr()` and `DynPrint()` both delegate to `hostabi.FormatScalar(i, params[0])`. `FormatScalar`'s KindRef branch tries `LoadStr` and returns `"None"` on failure:

```go
case vmtypes.KindRef:
    if v.Ref() == 0 { return "None" }
    s, err := LoadStr(i, v)
    if err != nil { return "None" }  // ← lists, dicts, arrays land here
    return s
```

The static `str()` path uses `hostabi.StringFunction(typ)` → `FormatValue(i, v, typ)` which has full container rendering with cycle detection. The dynamic path can't use `FormatValue` because it requires a compile-time source type.

A fix would add probes in the `DynStr`/`DynPrint` host function bodies: when `FormatScalar` returns `"None"` for a non-null ref, try `ArrayElems` to render `[elem, ...]`, then try loading as a map to render `{k: v, ...}`. This mirrors `FormatValue` but guided by runtime type discovery rather than source types.

## intPow silent zero for negative exponents

```go
func intPow(base, exp int64) int64 {
    if exp < 0 {
        return 0  // Python: 2**-1 → 0.5
    }
    ...
}
```

`dynBinary` calls `intBinary` when both operands are `KindI64`, and `intBinary` delegates to `intPow`. The fix: in `intBinary`, when `op == token.DOUBLESTAR && right < 0`, fall through to float arithmetic (`math.Pow(float64(left), float64(right))`) and return `BoxF64`.
